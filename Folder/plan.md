# Project Plan

## Project Overview

The goal of this project is to create a two-page personal portfolio website and publish it through GitHub Pages. The project also includes documentation that explains the planning process, risks, project scope, and final reflection.

Breaking the project into smaller tasks will make it easier to manage and will help prevent me from waiting until the last minute to complete everything.

## Risk Analysis Using TAME

The TAME framework helps identify possible risks before they become bigger problems. For this project, I considered the threats, assumptions, mitigations, and evaluation of each major risk.

### Risk 1: Time Management

**Threat:** One of the biggest risks is running out of time because I am balancing school assignments with a full-time work schedule.

**Assumption:** I assume I will have enough time to complete the project if I divide it into smaller tasks instead of trying to complete everything at once.

**Mitigation:** I will work on the planning documents and website in separate stages. I will prioritize the required features before spending time on optional improvements.

**Evaluation:** I will check my progress after each stage. If I fall behind, I will focus on completing the minimum project requirements before adding anything extra.

### Risk 2: GitHub or GitHub Pages Problems

**Threat:** I have had problems with GitHub and GitHub Pages during previous assignments, including changes not appearing correctly or difficulty finding the live version of the website.

**Assumption:** I assume the website will work if the files are named correctly, uploaded to the correct location, and GitHub Pages is configured properly.

**Mitigation:** I will test the website locally first and then test the GitHub Pages link after uploading the files. I will also make sure `index.html` is located in the root directory.

**Evaluation:** I will open the live website in a browser and test every navigation link. If something does not work, I will check the repository structure and file paths before making other changes.

### Risk 3: HTML or CSS Errors

**Threat:** A small error in HTML or CSS could cause the website layout or styling to not appear correctly.

**Assumption:** I assume keeping the code simple will make errors easier to identify and fix.

**Mitigation:** I will use one external stylesheet and keep the page structures similar. I will test changes regularly instead of making many changes before checking the website.

**Evaluation:** I will compare both pages to make sure the navigation, colors, spacing, and fonts remain consistent.

## Definition of Success

The project will be successful when all required files are included in the public GitHub repository, both website pages work correctly, the design is consistent, GitHub Pages displays
the website, and all documentation is complete. The project does not need advanced features to be successful. The most important goal is creating a complete, organized, and functional project package.
